# Bootstrap Seed Nodes

The seed nodes admitted into the experimental corpus graph by `spec_graph_import` during initial bootstrap.

Each file carries the kind + contract + payload for one seed node. The MCP server populates admission-context fields (organization_id, submitter, hashes, signature_chain, admitted_at, node_id) from its config and the admission ceremony at admission time — those fields are NOT in the seed files. Files are admitted in filename order (`001_` first, then `002_`, …).

## Discipline

- Files are LOCKED once committed. Changes require explicit per-file authorization.
- Content is authored to be authoritative on its own merits — no references to existing on-disk specs, no "prior art" citations, no "matches VOLT §X" framing.
- Re-admissions follow the per-node `contract_monotonicity_rule` defined inside each node's contract.
- New seed nodes are added as additional files (`003_`, `004_`, …); existing files are not edited without explicit per-file authorization.
- Each file is the canonical, locked, authoritative form of its node. The MCP server's `spec_graph_import` consumes these verbatim.
